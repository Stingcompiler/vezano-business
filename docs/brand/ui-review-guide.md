# وثيقة مراجعة وتطوير الكروت والواجهات — الإصدار المحدث

تتكوّن هذه الوثيقة من ثلاثة أجزاء تُستخدم في أوقات مختلفة:

| الجزء | متى يُقرأ | من يملؤه |
|---|---|---|
| **أ. القواعد العامة** | قبل أي عمل على الواجهة في أي مشروع | ثابت لكل المشاريع |
| **ب. ملحق المشروع** | مع الجزء أ، في المشروع المعني | يُملأ مرة واحدة لكل مشروع ويُحدَّث عند تغيّر القرارات |
| **ج. سكربت اللقطات** | يُشغَّل قبل المراجعة وبعد كل دفعة تنفيذ | يُكتب مرة واحدة لكل مشروع |

ملحق المراجع والاتجاهات في آخر الوثيقة لا يُقرأ إلا عند مرحلة الاستكشاف.

---

## الجزء أ — القواعد العامة

### الهدف

راجع شاشات المشروع ومكوناته وعالج التصاميم النمطية التي تجعل الواجهة تبدو مبنية بقالب جاهز. طوّر تصميمًا حديثًا وواضحًا يناسب طبيعة التطبيق وهويته، مع الحفاظ على الوظائف والبيانات وسهولة الاستخدام. المحتوى أولًا، والزخرفة تابعة له.

هذه معايير جودة وحدود تنفيذ، لا قالب يُنسخ. الاتجاه البصري والتكوين والحركة قرارات تتخذها أنت وفق المشروع.

### 1. النطاق

- اعمل ضمن ما يحدده ملحق المشروع: المنصات، أحجام العرض، اللغات، أوضاع الألوان، المكتبة، الخط. لا تضف منصة أو وضعًا أو لغة لم يُطلب.
- ما لم يحسمه الملحق، استنتجه من النظام القائم واذكر افتراضك في التقرير. لا توقف العمل بسبب قرار روتيني.
- لا تغيّر البيانات أو منطق العمل أو واجهات الـ API ضمن مهمة تصميم. إن احتجت تغييرًا في السلوك، اذكره كاقتراح منفصل.

### 2. ثلاثة قرارات مستقلة

لكل كرت أو وحدة عرض، اتخذ القرارات التالية منفصلة ولا تدع أحدها يفرض البقية:

1. **المظهر:** مسطّح، أو سطح مصبوغ بخفة، أو ذو حد دقيق، أو ذو عمق (ظل محسوب).
2. **التكوين:** أفقي، عمودي، شبكي، أو قائم على معاينة/صورة.
3. **السلوك:** عرض فقط، أو تنقّل (الكرت كله رابط)، أو اختيار، أو توسّع، أو إجراءات متعددة مستقلة.

شبكة Bento لا تفرض زجاجية، والكرت القابل للاختيار لا يفرض ظلًا، والتكوين الأفقي لا يفرض صورة.

### 3. الأنماط الممنوعة

النمط المولّد ليس نمطًا واحدًا بل عائلة. يُمنع ما يلي عندما يكون الهدف منه تمييز الحالة أو إضفاء "مظهر" دون وظيفة:

- **الشريط الملوّن:** صندوق مسطّح بشريط رفيع ملوّن أعلى الكرت أو على جانبه (بحد، أو تدرج، أو عنصر زائف، أو ظل داخلي، أو عنصر منفصل) مع شارة تكرر الحالة نفسها.
- **الأيقونة في الدائرة المصبوغة:** أيقونة داخل دائرة أو مربع بخلفية فاتحة من لون الحالة في زاوية الكرت، دون أن تضيف معنى.
- **كرت إحصائية لكل رقم:** تحويل كل قيمة رقمية في الشاشة إلى كرت مستقل بأيقونة وعنوان ورقم كبير.
- **الصف الثلاثي أو الرباعي المتساوي:** توزيع المحتوى على كروت متساوية الحجم افتراضيًا بغض النظر عن أهميته.
- **أيقونة على كل عنوان:** إلصاق أيقونة بجانب كل عنوان قسم أو كرت.
- **التدرج اللوني على الأزرار والعناوين** دون أن يكون جزءًا من هوية المنتج المحسومة.
- **الحركة التلقائية المستمرة:** نبض، أو ارتفاع، أو توهّج على عناصر ساكنة لا تمثل عملية جارية.
- **كرت داخل كرت** دون حاجة وظيفية.

عند وجود أي منها، أعد بناء التكوين جوهريًا: ترتيب المعلومات، العنوان، الحالة، المسافات، الأسطح، الإجراءات. حذف العنصر المخالف أو تغيير لونه وحده لا يكفي.

**الحالة** تُنقل بنص واضح، تدعمه أيقونة عند الفائدة، ويدعمه اللون دون أن يكون الوسيلة الوحيدة. لا تُكرر الحالة في أكثر من موضع في الكرت الواحد دون سبب.

**الاستثناءات الوظيفية** لا يشملها المنع: مؤشرات التقدم، حدود التركيز، حدود الحقول، أشرطة التنبيه العامة، المؤشر الجانبي لعنصر التنقل النشط، خط الاقتباس. وثّق أي استثناء آخر في التقرير.

### 4. التكوين تابع للمحتوى

لكل كرت حدد: ما موضوعه، وما أهم معلومة تُفهم أولًا، وما التفاصيل المساندة، وما الإجراء الرئيسي إن وجد. ثم:

- امنح العنوان مساحة كافية ولا تفرض ارتفاعًا أو نسبة أبعاد تقص المحتوى. توحيد الأبعاد مقبول عندما يخدم المقارنة بين عناصر متماثلة الطبيعة.
- افصل بصريًا بين المحتوى الرئيسي والبيانات الثانوية والإجراءات.
- اجعل عدد الأعمدة تابعًا للمساحة والمحتوى ضمن نطاق المنصة.
- استخدم الصفوف أو القوائم أو الجداول أو الأقسام المفتوحة عندما تكون أوضح من الكروت. ليس كل شيء كرتًا.
- افصل بين أنواع الكروت التي يحتاجها المشروع فعلًا (معلومات، حالة، إجراء، معاينة، اختيار). نوّع التكوين بين الوظائف، وحافظ على الاتساق داخل الوظيفة الواحدة. لا تنشئ متغيرات لا تُستخدم.
- استخدم المكوّن المشترك الموجود وطوّره، واتبع أسماء المشروع وتقنياته. لا تُدخل مكتبة جديدة إذا كان النظام القائم كافيًا.

### 5. اللون والحدود والظلال والحركة

- لا تفرض ظلًا أو صبغة أو حدًا ملوّنًا على كل كرت. الفصل بالمسافات وحدها مقبول.
- مجموعة ألوان هادئة، والتأكيد القوي للأولويات الحقيقية فقط. إذا كانت كل العناصر بارزة بالقوة نفسها فأعد توزيع التأكيد.
- الزجاجية والتأثيرات ثلاثية الأبعاد عند ملاءمة السياق وبقاء المقروئية والأداء، لا كأساس افتراضي. عند اتباع نمط Apple، لا تعمّم Liquid Glass على طبقة المحتوى.
- الحركة لتوضيح تغيّر الحالة أو نتيجة الإجراء أو التوسّع أو إعادة الترتيب: تحويم للعناصر التفاعلية على سطح المكتب، استجابة ضغط واضحة، انتقال سلس عند كشف التفاصيل. احترم `prefers-reduced-motion`، ولا تخفِ معلومات أو إجراءات أساسية حتى التحويم، ولا تحرّك التخطيط.
- تجنّب الضبابية والحركات المستمرة على القوائم الكبيرة.

### 6. السلوك والوصول والعربية

- يجب أن يفهم المستخدم هل الكرت يعرض، أو يفتح، أو يختار، أو يحتوي إجراءات مستقلة. الكرت ذو الإجراء الواحد يُبنى ببنية دلالية مناسبة؛ الكرت متعدد الإجراءات يجعل أهدافها مستقلة دون تداخل نقر.
- وفّر: تفاعلًا بلوحة المفاتيح وترتيب تركيز منطقيًا، مؤشر تركيز واضحًا، أسماء مفهومة لعناصر التحكم، حالة اختيار مرئية تتجاوز تغيّر اللون، تباينًا مقروءًا على الخلفية الفعلية، وأحجام تفاعل تناسب وسائل الإدخال المدعومة.
- في العربية: استخدم الخصائص المنطقية (`margin-inline-start` و`text-align: start` ونظائرها في المكتبة)، وتحقق من التفاف العناوين، والمحتوى المختلط (أرقام، رموز، أسماء لاتينية) في الجداول والقوائم، واتجاه الأيقونات ذات الدلالة الاتجاهية. قرار الأرقام والخط محسوم في ملحق المشروع ولا يُعاد فتحه.

### 7. الحالات الواقعية

تحقق لكل كرت ووحدة من: نصوص طويلة وقيم كبيرة وبيانات ناقصة؛ تحميل وفراغ وخطأ ونجاح؛ اختيار وتعطيل وفقدان اتصال عند وجودها؛ عدد عناصر صفر وواحد وكثير. حافظ على استقرار التخطيط أثناء التحميل، واجعل العناصر المؤقتة قريبة من أبعاد المحتوى المتوقع، ووضّح سبب التعطيل عندما يحتاج المستخدم معرفته.

### 8. سير العمل

1. **اقرأ** ملحق المشروع وملف تعليمات الواجهة.
2. **شغّل سكربت اللقطات** لتسجيل الوضع الحالي، وشغّل الفحص النصي (قسم 10).
3. **راجع اللقطات بصريًا** واحصر الشاشات والمكونات المشتركة. فحص الكود وحده ليس مراجعة بصرية. إذا تعذّر التقاط شاشة فاذكر ذلك صراحة.
4. **دوّن المشكلات:** الشاشة، المكوّن، الملاحظة، تأثيرها على الاستخدام، المعالجة المقترحة. حافظ على الأجزاء الجيدة. البساطة والخلفية البيضاء وتكرار المكونات ليست مشكلة بذاتها.
5. **استكشف** اتجاهين أو ثلاثة على شاشة واحدة تمثيلية بمحتوى واقعي، إذا كان الاتجاه غير محسوم في الملحق أو التغيير واسعًا. قارن بحسب وضوح المعلومات، ملاءمة الكثافة، الانسجام مع الهوية، سهولة القراءة، قابلية إعادة الاستخدام، والأداء.
6. **نقطة التوقف الوحيدة:** اعرض لقطات الاتجاهات مع توصيتك وانتظر الاختيار. بعد الاختيار سجّله في ملحق المشروع ولا تتوقف للموافقة على التفاصيل الروتينية.
7. **نفّذ على دفعات:** المكوّن المشترك أولًا، ثم ترحيل الشاشات في دفعات مستقلة يمكن مراجعة كل منها على حدة. لا تغيّر البيانات أو السلوك في نفس الدفعة.
8. **بعد كل دفعة** شغّل اللقطات والفحص النصي والاختبارات المتاحة، وراجع اللقطات فعليًا.

### 9. التحقق والتسليم

راجع جميع الشاشات المتأثرة ضمن المنصات وأحجام العرض واللغات وأوضاع الألوان المدعومة فعلًا. تحقق من معالجة الأنماط المحددة في المراجعة الأولى، ووضوح المحتوى والإجراءات، واتساق المكونات المتشابهة، وعدم وجود قص أو تداخل أو قفزات تخطيط، وسلامة الوظائف والبيانات. لا تدّعِ تنفيذ اختبار أو مراجعة لم تحدث.

التقرير النهائي يتضمن:

1. نطاق المراجعة والشاشات التي فُحصت فعليًا (مع مسار اللقطات).
2. المشكلات المكتشفة.
3. الاتجاه المختار وسبب ملاءمته.
4. التعديلات المنفذة والمكونات المشتركة المعالجة.
5. نتائج التحقق الفعلية: الفحص النصي قبل وبعد، الاختبارات، اللقطات.
6. الافتراضات والاستثناءات والقيود وما تعذّر التحقق منه.

### 10. الفحص النصي ومنع العودة

- أضف القواعد المتفق عليها إلى ملف تعليمات الواجهة الذي يُقرأ قبل بناء الشاشات، وسجّل قرار التصميم وأسبابه في توثيق المشروع.
- وفّر أمر فحص واحدًا مناسبًا لتقنيات المشروع يكشف التطبيقات المعروفة للأنماط الممنوعة: يعرض المواضع وينتهي بالفشل عند وجودها، وينتهي بنجاح دون مخرجات عند خلوّ النطاق، ويسمح باستثناءات موثقة بتعليق محدد.
- الفحص النصي يكشف أنماطًا محددة فقط ويمكن الالتفاف عليه. لا يحكم على الأناقة ولا يغني عن المراجعة البصرية؛ قيمته أنه رخيص ويمنع التراجع العرضي.

## الجزء ب — ملحق المشروع (قالب يُملأ مرة واحدة)

> يُحفظ في المشروع باسم واضح (مثل `docs/ui-profile.md`) ويُشار إليه من ملف تعليمات الواجهة. ما يُحسم هنا لا يُعاد استنتاجه.

**اسم المشروع:**

**نوع التطبيق والمهام الرئيسية للمستخدم:**
(مثال: نظام إدارة فندقي؛ الاستقبال يسجّل الوصول والمغادرة ويعرض حالة الغرف، المدير يراجع الإشغال والفواتير.)

**المستخدمون وطبيعة الاستخدام:**
(قراءة سريعة، مقارنة، تشغيل متكرر طوال اليوم، إدارة، استكشاف. كثافة المعلومات المطلوبة: منخفضة / متوسطة / عالية.)

**المنصات ووسائل الإدخال:**
(ويب سطح مكتب بفأرة ولوحة مفاتيح / ويب جوال باللمس / تطبيق جوال / سطح مكتب أصلي.)

**أحجام العرض المدعومة:**
(الحد الأدنى والأقصى لعرض النافذة، ونقاط التحول المعتمدة.)

**اللغات والاتجاه:**
(عربية RTL فقط / عربية + إنجليزية مع تبديل / إنجليزية فقط.)

**الخطوط:**
(الخط العربي، والخط اللاتيني المزاوج إن وُجد، وأوزانها، وارتفاع السطر الأساسي.)

**الأرقام:**
(لاتينية 0-9 في كل الواجهة / عربية-هندية ٠-٩ / حسب لغة الواجهة. القرار نهائي وينطبق على الجداول والفواتير والتقارير.)

**أوضاع الألوان:**
(فاتح فقط / داكن فقط / كلاهما مع تبديل. أي وضع غير مذكور هنا غير مدعوم.)

**المكتبة ونظام التصميم:**
(مثال: Next.js + Tailwind + shadcn/ui؛ ملف الرموز `tailwind.config` والمتغيرات في `globals.css`؛ مكوّن الكرت المشترك في `components/ui/card.tsx`.)

**المكونات المشتركة الموجودة التي يجب البناء عليها:**

**هوية المنتج بكلمات قليلة:**
(مثال: احترافي، هادئ، كثيف المعلومات، بلا زخرفة؛ أو: دافئ، مرحّب، كروت معاينة بصور.)

**الاتجاه البصري المختار:**
(يُملأ بعد مرحلة الاستكشاف ونقطة التوقف. المظهر / التكوين الغالب / الاستثناءات.)

**الشاشات التمثيلية للاستكشاف واللقطات:**
(ثلاث إلى خمس شاشات تغطي أنواع الكروت المختلفة، مع الحالات المهمة لكل منها.)

**استثناءات موثقة من الأنماط الممنوعة:**

**أمر الفحص النصي:**
(مثال: `npm run lint:ui`)

**أمر اللقطات:**
(مثال: `npm run shots`)

**قيود البيئة:**
(مثال: يجب أن تعمل الشاشات الأساسية بلا اتصال؛ أجهزة ضعيفة؛ شاشات قديمة منخفضة الدقة.)

## الجزء ج — سكربت اللقطات

الغرض: أمر واحد يُنتج لقطات كل الشاشات التمثيلية بالأحجام والحالات المدعومة في مجلد واحد، قبل التعديل وبعده، لتكون المراجعة البصرية فعلية وقابلة للتكرار.

المتطلبات:

- يشغّل التطبيق (أو يفترض أنه يعمل على منفذ محدد) ويسجّل الدخول بحساب تجريبي ببيانات واقعية: نصوص طويلة، قيم كبيرة، قوائم فارغة وممتلئة.
- يلتقط كل شاشة من قائمة الشاشات التمثيلية في الملحق، بكل حجم عرض مدعوم، وبكل وضع ألوان مدعوم، وبكل لغة مدعومة.
- يلتقط الحالات المهمة (فارغ، محمّل، خطأ، تحديد) حيث يمكن الوصول إليها عبر مسار أو معلمة.
- يعطّل الحركة (`prefers-reduced-motion`) ويثبّت التاريخ والبيانات لتكون اللقطات قابلة للمقارنة.
- يحفظ النتائج في `shots/<تسمية الدفعة>/<الشاشة>--<العرض>--<الوضع>--<اللغة>.png`.

هيكل مرجعي بـ Playwright (يُعدَّل وفق المشروع):

```ts
// scripts/shots.ts
import { chromium, devices } from "playwright";

const BASE = process.env.BASE_URL ?? "http://localhost:3000";
const LABEL = process.argv[2] ?? "current";

// من ملحق المشروع
const VIEWPORTS = [
  { name: "desktop-1280", width: 1280, height: 800 },
  { name: "desktop-1920", width: 1920, height: 1080 },
];
const SCHEMES: Array<"light" | "dark"> = ["light"];
const LOCALES = ["ar"];
const SCREENS = [
  { name: "rooms", path: "/rooms" },
  { name: "rooms-empty", path: "/rooms?demo=empty" },
  { name: "bookings", path: "/bookings" },
  { name: "booking-detail", path: "/bookings/demo-long-names" },
  { name: "invoices", path: "/invoices" },
];

(async () => {
  const browser = await chromium.launch();
  for (const vp of VIEWPORTS) for (const scheme of SCHEMES) for (const locale of LOCALES) {
    const ctx = await browser.newContext({
      viewport: { width: vp.width, height: vp.height },
      colorScheme: scheme,
      locale,
      reducedMotion: "reduce",
      storageState: "scripts/auth.json", // جلسة الحساب التجريبي
    });
    const page = await ctx.newPage();
    await page.clock.setFixedTime(new Date("2026-01-15T10:00:00"));
    for (const s of SCREENS) {
      await page.goto(`${BASE}${s.path}`, { waitUntil: "networkidle" });
      await page.screenshot({
        path: `shots/${LABEL}/${s.name}--${vp.name}--${scheme}--${locale}.png`,
        fullPage: true,
      });
    }
    await ctx.close();
  }
  await browser.close();
})();
```

للمشاريع التي تستخدم Storybook، يُضاف التقاط القصص الخاصة بالمكوّن المشترك بنفس المصفوفة، فهي أسرع في مرحلة استكشاف الاتجاهات.

### مثال على الفحص النصي (Tailwind)

```bash
# scripts/lint-ui.sh — ينتهي بالفشل عند وجود مخالفات غير مستثناة
PATTERN='border-(l|r|s|e|t|b)-(2|4|8)\b|border-\[(2|3|4|5|6)px\]|rounded-full (bg-\w+-(50|100))'
HITS=$(grep -rnE "$PATTERN" src --include='*.tsx' --include='*.jsx' --include='*.css' | grep -v 'ui-allow:')
if [ -n "$HITS" ]; then echo "$HITS"; exit 1; fi
```

الاستثناء يوثَّق بتعليق في السطر نفسه، مثل `{/* ui-allow: مؤشر التنقل النشط */}`. النمط أعلاه مثال يُضبط وفق المشروع، ويُراجع عند ظهور التفاف جديد.

## ملحق — اتجاهات مرجعية ومراجع (يُقرأ عند الاستكشاف فقط)

اتجاهات للاختيار منها أو الجمع بينها، لا قائمة إلزامية:

| الاتجاه | خصائصه | يناسب |
|---|---|---|
| الهادئ الدقيق | محاذاة محكمة، أسطح متقاربة، زخرفة محدودة | الإداري والاحترافي |
| الأسطح المصبوغة | صبغة خفيفة على كامل سطح الكرت بدل الحد | الملخصات والتعليمي |
| العمق الناعم | ظل خفيف للعناصر المهمة فقط | إجراء رئيسي أو محتوى يحتاج تأكيدًا |
| كروت المعاينة | صورة أو معاينة حقيقية مع عنوان وتفاصيل | الملفات والمنتجات والدورات |
| الوحدات المسطّحة | فصل بالمسافات أو الحدود الدقيقة دون ظلال | لوحات التشغيل والمحتوى الكثيف |
| التكوين الأفقي | معاينة ومعلومات وإجراءات على عرض النافذة | سطح المكتب والطلبات |
| شبكات Bento | أحجام متفاوتة تعكس الأولوية | صفحات البداية وعرض المزايا |
| كروت الاختيار والتوسّع | حالة اختيار واضحة أو كشف تدريجي | الخطط والإعدادات والقوالب |
