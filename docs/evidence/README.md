# ملف الأدلة — بوابات المراحل ١ و٢ و٣ (§١٨.٤ · §١٥.٥ · MK-1…4)

لكل معيار: الاختبار، commit، بيانات الاختبار، الجهاز، النتيجة، العيوب المفتوحة. **نجاح فحص الوثيقة لا يسجّل نجاحاً لأي ACC** — يسجَّل هنا ما ثبت آلياً، وما ثبت يدوياً بجهازه، وما لم يُثبت بعد.

## البيئة الآلية
- الاختبار: `apps/web/e2e-gate/*.spec.ts` بـ`pnpm --filter @sting/web e2e:gate` (Playwright، سياقان = جهازان، Chromium بلا رأس @1440) على **خادم Django حقيقي** (PostgreSQL 16، `STING_ENV=ci`، `STING_FAULTS_ENABLED=1`) — لا `page.route`. Next يمرّر `/api/*` إلى Django بنفس الأصل (`STING_API_UPSTREAM`).
- الحالة الابتدائية (§١٥.٤) قبل كل تجربة بـ`POST /api/scenario/reset`: عميل «أحمد الطيب — تجريبي» برصيد صفر وحدّ ائتمان 1,000.00؛ «سكر» 10 كغ (افتتاحي معتمد) بسعر 100.00/كغ؛ الصندوق صفر (وردية تُفتح بـ0.00)؛ جهازان يُسجَّلان من المتصفح فعلاً (تسجيل + تنزيل أول).
- المحاكاة المعزولة عن الإنتاج: `drop_ack` (الخادم يطبّق ويلتزم ثم يخفي الردّ)، `freeze_reconciliation`/`network_cut` (الخادم لا يطبّق شيئاً)، `printer_fail`، `verify_send_fail`، `sms_*` (مزوّد الرسائل)، `po_send_fail`، `maintenance` (إعلان صيانة على صفحة الحالة)؛ الاشتراك بـ`POST /api/scenario/subscription {state, days_since_expiry, plan_code}` والإذن التسويقي بـ`POST /api/scenario/marketing`؛ وسوق المرحلة ٣ بـ`POST /api/scenario/market` (بائع «ب» بقائمة تحقق مكتملة بانتظار المراجعة وباقة «فرعان»، مسودّتا عرض عام وخاص بقائمة أسعار عضوها «أ»، مالك نشط للثالثة «ج» `+249912447003`، ومشغّل منصة برمز جلسة مباشر). قطع الشبكة على الجهاز = إسقاط `/api/*` وإعلان «بلا اتصال» (خادم Next التطويري يخدم أجزاء المسارات عند الطلب فلا `setOffline`).
- ما يُحاكى في المتصفح فقط: منح التخزين الدائم (`navigator.storage.persist`) لأن Chromium بلا رأس لا يمنحه لأي موقع — المنح الحقيقي يُتحقق يدوياً على الجهاز.
- التشغيل: CI job `gate` في `.github/workflows/ci.yml`؛ محلياً يحتاج قاعدة `sting_gate_test` (`createdb sting_gate_test`).

## خطوات التجربة اليدوية للمالك (لكل سيناريو آلي)
1. `cd backend && STING_ENV=development STING_FAULTS_ENABLED=1 uv run python manage.py scenario reset` — يطبع الحساب (`+249912447001` / `sting-demo-2026` / PIN `123456`).
2. جهازان (متصفحان أو هاتف وحاسوب): `/login?next=/setup-device` → اختر «بقالة النيل — تجريبي» → انتظر «الجهاز جاهز» → افتح وردية بـ0.00.
3. نفّذ صف التجربة من جدول §١٥.٤ ثم تحقق من الشاشات: كشف العميل (العملاء والذمم → أحمد الطيب)، الوردية والصندوق، المخزون. المفاتيح: `POST /api/scenario/faults {"key":"drop_ack","on":true}` وغيرها.
4. النتيجة المتوقعة = عمود «النتيجة المتوقعة» في §١٥.٤ حرفياً. أي فرق يُسجَّل هنا في «العيوب المفتوحة» مع commit والجهاز.
5. **تجربة السوق (§١٥.٥) يدوياً**: بعد `reset` نفّذ `curl -X POST http://localhost:8000/api/scenario/market` (يطبع رمز المشغّل وحساب الثالثة `+249912447003`). بمتصفح المشغّل `/platform/login` (حساب مشغّل بسرّ TOTP يُنشأ عبر `stingops.services.ensure_operator` — انظر 0005 §٨١؛ في البوابة الآلية يُستعمل رمز الجلسة الذي يعيده `scenario/market`) → «طلبات التحقُّق» → «تُحقّق من المنشأة» لمخزن البركة. بحساب المالك في «مخزن البركة»: `/market/offers` → انشر «سكر أبيض» (عام) و«أرز بسمتي» (خاص). بحساب «بقالة النيل»: `/market` ابحث «سكر» → أضف 10 → أرسل الطلب؛ اقطع الشبكة قبل الردّ وأعد الإرسال → طلب واحد في «طلباتي». بـ«مخزن البركة»: الواردة → عرض سعر بـ8 → أرسل؛ «بقالة النيل» تقبل → «مخزن البركة» تشحن 8 → «بقالة النيل» تستلم 7 بسبب. تحقق: «الدفع» يُظهر المستحقّ 7×118000 فقط، وإعادة الاستلام مرفوضة. بحساب الثالثة (`+249912447003`): «أرز بسمتي» غير موجود والطلب لا يظهر. بالمشغّل: «M0» → «احسب الآن» → «غير حاسم».
